# 스레드 답글 스킬 — @solopreneur.jm (남의 글에 답글 → 프로필 방문·팔로우)

이 스킬은 **글쓰기(SKILL 형제 `threads-post`)가 아니라 "답글 달기"** 를 담당한다.
`threads-strategy.md` §5가 규정한 **채널 성장의 최대 지렛대**를 실행으로 옮긴 것.
목표: 답글 → 상대 관중석에 노출 → **프로필 클릭(공식 랭킹 신호)** → 팔로우. **답글에서 팔지 않는다. 프로필이 판다.**

## 0. 두 가지 모드 — 먼저 어느 쪽인지 고른다

| | **모드 A · 배치 스캔** (기본) | **모드 B · 대댓글** → `reply-to-reply.md` |
|---|---|---|
| 언제 | "댓글 써줘" — 타깃을 찾아야 할 때 | 사용자가 **원글+댓글을 붙여넣거나 캡처를 첨부**했을 때 |
| 하는 일 | 스레드 검색 → 10건 고름 → 초안 → 카드 UI | 그 대화 하나에 달 **추천안 3개**를 채팅으로 |
| 출력 | 브라우저 승인 카드 | 채팅 텍스트 (카드 없음) |
| 발행 | 카드 대기열 → 사용자가 "발행" | 사용자가 번호 선택 |

**입력에 원글·댓글 내용이 이미 들어 있으면 모드 B다.** 아래 §1~§6은 모드 A 기준이고, 가드레일(§1)은 두 모드 공통이다.

### 모드 A — 무엇이 필요한가

- **입력**: 어느 니치를 돌지(발달장애 육아 / 시니어·치매 예방 / 공인중개사 / 바이브코딩 메이커 / 혼합), 몇 개 뽑을지(기본 10).
- **출력**: 브라우저에 뜬 글래스모피즘 **승인 카드** + (사용자 발행 지시 시) 실제 스레드 답글.
- **전제**:
  1. Claude-in-Chrome이 **@solopreneur.jm 로 로그인된 크롬**에 연결돼 있어야 한다. (§6 계정 함정 참고)
  2. 원재료(하성재 정체성·앱 실데이터)는 `src/projects.js`와 `threads-strategy.md` §2에서 가져온다. 지어내지 않는다.

## 1. 절대 규칙 (가드레일 — 어기면 계정이 죽는다)

1. **애스트로터핑 금지.** 내가 만든 앱을 **제3자인 척** 흘리지 않는다. 앱을 언급하려면 **"제가 만들었어요"라고 밝힌다**(정직). 정체 숨긴 반복 홍보 답글 = Meta 비진정성 행동 → 도달 축소·정지.
2. **앱 언급은 10개 중 1개 이하.** 나머지는 순수 공감. 답글의 임무는 **프로필 클릭을 얻는 것**이지 파는 게 아니다(§5).
3. **답글에 링크 금지.** URL을 붙이지 않는다. 프로필/bio/고정글이 홍보를 맡는다.
4-B. **시니어·치매 예방 니치(기억정원) = 의료 단정 0.** 진단·처방·"이러면 예방된다"를 절대 쓰지 않는다. 그리고 **소아 발달 전자책을 근거로 끌어오지 않는다**(코퍼스가 다르다 — `domain-knowledge.md` §6). 무거운 글(투병·임종·요양원 결정)은 건드리지 않는다. 상세는 §2-3.
4. **발달장애 육아 니치 = 앱·홍보 0.** 이 니치엔 앱을 절대 얹지 않는다(상처가 된다). 다만 **진짜 질문이 있는 글에는 근거 있는 답**을 준다 → `domain-knowledge.md`(짱샘의 책방 전자책 기반, 배치당 최대 1건). 감정·사연·일상 글은 **순수 공감**이고, 묻지 않은 사람에게 지식을 얹으면 훈수다. **유산·상실·심각한 우울 글은 아예 건드리지 않는다**(낯선 메이커의 어떤 답글도 침범이 된다).
   - ⛔ **하성재는 치료사가 아니다.** "치료실에 왔던 아이가…" 류의 임상 경험 서술은 경력 사칭 → `domain-knowledge.md` §1 정체성 경계 필수.
5. **휴먼인더루프 발행.** 절대 자동 발행하지 않는다. **사용자가 카드에서 "발행 완료"를 켜고 "발행"을 누른(=대기열에 담은) 것만** 발행한다. 공개 답글은 본인 이름으로 나가므로 최종 결정은 사용자 몫.
6. **AI 티 자가검증 통과 전에는 카드에 올리지 않는다**(§3, `ai-tell-checklist.md`).
7. **톤**: 따뜻한 존댓말 구어체(`threads-strategy.md` §2, `threads-post/SKILL.md` §2). 이모지 절제.
8. **홍보·광고성 글엔 답글 달지 않는다(사용자 지시 2026-07-25).** 조회수·주제만 보고 고르지 말 것 — **파는 글**에 단 답글은 그들에게 안 읽히고, 홍보 답글 무리에 묻히고, 진짜 관계(=프로필 클릭)를 못 만든다. 판별·예외는 §2-2 타깃 선정 필터.

## 2. 워크플로 (이 순서를 지킨다)

### 2-1. 브라우저 연결 확인 (§6)
`list_connected_browsers` → **@solopreneur.jm** 계정 크롬인지 확인. 여러 프로필이 떠 있으면 `AskUserQuestion`으로 고르게 하고 `select_browser`. threads.com 홈에서 좌측 프로필이 `solopreneur.jm`인지 스크린샷으로 검증.

### 2-2. 타깃 글 스캔
니치별 검색 URL: `https://www.threads.com/search?q=<URL인코딩>&serp_type=default&filter=recent`
- **`filter=recent` 우선**(답글은 최근 글이어야 의미). 단, 흔한 단어(치료·매물 등)는 잡음이 많다 → **니치 전용 용어**를 쓴다.
- **인기순(filter 없음)은 2024~2025 오래된 글이 섞인다** → 최근글이 없을 때만 보조로.
- 검색어 예시(실측 기준, 이기는 것 위주):
  - 발달장애 육아: `느린아이`(부모 사연 풍부) · `발달지연` · `언어치료 대기` · `자폐스펙트럼` — (⚠️ `발달센터`·`바우처`는 센터·업체 광고가 대부분)
  - 시니어·치매 예방(기억정원): `부모님 치매` · `치매 초기` · `경도인지장애` · `부모님 건강` · `요양원 고민` — (⚠️ `치매예방`·`인지훈련`은 센터·보험·건강식품 광고가 대부분 → 필터 필수)
  - 공인중개사: `공인중개사` · `부동산 중개` · `임장` — (수험생·마케팅이 섞이니 **일하는/고민하는 중개사** 글을 고른다)
  - 메이커(팔로워 엔진): `바이브코딩`(가장 신선·활발) · `1인개발` · `사이드프로젝트`
- 본문 읽기: `get_page_text`. 퍼머링크·전문 추출: `javascript_tool`로
  ```js
  [...document.querySelectorAll('a[href*="/post/"]')]  // → /@user/post/CODE (username이 href에 있음)
  ```
- **좋은 후보 = ① 최근(48h 이내 이상적) ② 진짜 고민·경험·따뜻함이 있음 ③ 답글이 아직 안 붐빔 ④ 홍보·광고성이 아님(아래 필터) ⑤ `reply-log.md`에 없는(=아직 답글 안 단) 계정.**
- **`reply-log.md`(이 폴더)를 먼저 읽어 이미 답글 단 계정은 제외한다.** 같은 사람 반복 답글은 스팸처럼 보인다. 발행 후 실제로 나간 것만 `reply-log.md`에 추가한다.

#### ★ 중복 제안 방지 — 로그만 믿지 말고 **스레드에서 직접 읽는다** (2026-07-26 사용자 지적)

`reply-log.md`는 **이 스킬로 발행한 것만** 담긴다. 그런데 실제로는 그 밖의 경로로도 답글이 나간다:
- 사용자가 카드 텍스트를 **직접 복사해 붙여넣은 것**(발행 실패 시 넘긴 텍스트 — 실제 사례)
- 사용자가 스킬 없이 혼자 단 답글

그래서 로그만 보고 고르면 **이미 답글 단 글을 또 제안한다.** 카드 만들기 전에 반드시:

1. **`https://www.threads.com/@solopreneur.jm/replies` 를 열어 실제 답글 이력을 읽는다.**
   ```js
   const s=new Set();
   document.querySelectorAll('a[href*="/post/"]').forEach(a=>{
     const m=(a.getAttribute('href')||'').match(/^\/@([^\/]+)\/post\/([A-Za-z0-9_-]+)/);
     if(m && m[1]!=='solopreneur.jm') s.add(m[1]+'/'+m[2]);   // 상대계정/글코드
   });
   JSON.stringify([...s])
   ```
   - ⚠️ 무거운 페이지다. 로딩에 15초 이상 걸리고 렌더러가 얼기도 한다 → 새 탭에서 열고 넉넉히 기다린다.
   - 스크롤해서 더 불러올수록 정확해진다. 최소 한 화면은 확보할 것.
2. 여기서 나온 **계정 + 글코드**를 후보에서 뺀다. 계정 단위로 빼면 안전하고, 글 단위로 빼면 같은 사람의 다른 글엔 달 수 있다.
3. 읽어온 목록을 `reply-log.md`에 **역방향 동기화**한다(수동 발행분이 그때 로그에 들어온다).

**그리고 사용자가 카드에서 '발행 완료'를 켜지 않은 것은 이유가 있는 것이다(2026-07-26 지시).** 미승인 카드는 다음 회차에 **다시 제안하지 않는다** — `reply-log.md`의 "제외" 표에 옮긴다.

#### ★ 타깃 선정 필터 (사용자 지시 2026-07-25) — "너무 자기 홍보용 글엔 굳이 달지 말 것"

  - 메이커: 동료 톤. "저도 ~" 반복 피하고 시작을 다양화.

### 2-4. AI 티 자가검증
`ai-tell-checklist.md`를 돌려 각 초안을 **다시 쓴다.** 통과 못 하면 카드에 안 올린다. (자연스러운 구어체·번역투 제거·기계적 대구 제거·정형 감탄 제거·시작 다양화)

### 2-5. 카드 UI 띄우기 (§4)
`card-ui.md`의 주입 기법으로 브라우저에 글래스모피즘 카드를 띄운다. 각 카드 = 원글 전문 + 수정가능 댓글 + 발행완료 토글, 우상단 발행 버튼.

### 2-6. 사용자 편집·발행
사용자가 카드에서 댓글을 고치고 **발행 완료** 토글을 켠 뒤 우상단 버튼을 누른다 → 완료된 카드가 `localStorage['threads_reply_queue']`에 담긴다 → 사용자가 채팅에 **"발행"**.

> ⚠️ **버튼 이름을 "발행"으로 짓지 말 것**(2026-07-26 실전 혼선). 브라우저 페이지는 Claude를 호출할 수 없어서, 버튼은 **대기열에 담기만** 하고 실제 게시는 채팅에서 시작된다. 버튼에 "발행"이라고 써 두면 사용자는 이미 발행한 줄 알고 "왜 또 발행하래?"가 된다. 버튼 문구는 **"✅ 승인 확정"**, 토스트는 **"이제 Claude에게 '발행'이라고 말해주세요"**로 한다.

### 2-7. 실제 발행 (§5)
`window.getPublishQueue()`(또는 `localStorage.threads_reply_queue`)를 읽어, 각 항목마다:
1. `https://www.threads.com{url}` 로 이동, **원글을 다시 읽어 카드의 원글과 일치하는지 확인**(특히 `verify:true` 카드 — 같은 유저가 최근글 여러 개일 때 오발행 방지).
2. 답글 작성창을 열어 댓글을 입력하고 **게시**.
3. 스크린샷으로 발행 확인. 하나씩, 순차로.
- 발행 후 사용자에게 요약 보고(몇 개 발행/스킵). 필요 시 `threads-log.md`엔 남기지 않아도 된다(운영 활동 — 사용자 지시 2026-07-25: 로그 과잉관리 하지 말 것).

### 2-8. 문체 학습 → 커밋/푸시 (발행 때마다, 사용자 지시 2026-07-25)
발행한 각 카드의 **최종본(수정했든 안 했든)을 AI 초안(`el.dataset.original`)과 대조**해 하성재님 말투를 학습한다.
1. diff에서 신호 추출 — 단어 교체·종결어미·감정표현(ㅠㅠ/ㅋㅋ/…)·이모지·해시태그·문장 길이·질문 방식·**지운 표현(금지 후보)**. 수정이 없어도 "그대로 통과 = 승인"으로 기록.
2. `threads-post/voice-profile.md`의 §규칙 갱신 + §관찰 로그에 날짜 항목 추가.
3. **커밋·푸시**: `voice-profile.md`만 스테이징(관계없는 작업트리 변경 섞지 말 것) → `learn(voice): <날짜> 발행본에서 문체 N건 학습`.
> 이 학습은 **두 스킬 공용**이다 — `threads-post`(글)도 같은 `voice-profile.md`를 읽으므로, 답글에서 배운 말투가 글쓰기에도 그대로 적용된다.
